# 活动与本地复刻

PC 1.15.0 的 30 个活动配置已接入九类玩法，另接入奖励关和 18 个遭遇活动。新增 65 条接口与原生路由、方法和字段契约对齐。当前完成范围是服务端实现与隔离验证，未重启真实服务、部署客户端或修改真实存档。

仍有实机资源缺口：活动页的 10 个背景预制体包缺失，涉及全部 30 个活动背景配置；另有 7 处 `SE_DUMMY` 音效引用需要确认原生容错。不能把后端测试通过理解为活动页面或完整剧情已实机通过。

## 档期、参加条件与存档

任务分类、条件礼包、功能解锁奖励与旧档迁移规则见 [解锁条件与旧档兼容](unlock-conditions.md)。

`gameplay-rules.json` 默认 `event_open_all=1`，使主表已有活动可选；设为 `0` 后可通过 `event_open_ids` 指定重开活动，空列表则按原日期。重开同时覆盖活动入口、关卡与剧情日期、相关任务、兑换期限，以及关联卡池和代币期限。

原始主表 blob、素材清单和存档仍绑定原始版本。服务端生成独立 `events-...` 资源版本，同步活动档期及关联日期。已发布的派生主表和元数据缓存在 `master/event-views/`，按内容哈希校验；四份内存视图的淘汰和进程重启不会使已发布 URL 失效。配置变化会更新资源版本，客户端的实际刷新时序尚未实机验证。

普通活动横幅按活动 ID 跳转，支持多期同类活动。遭遇活动的原生界面则固定选择日期有效的第一期，没有多期选择器，因此客户端主表按当前认证存档只开放所选的一档；首次使用默认首期。调用既有参加接口切换后，响应携带对应的新资源版本，不依靠参与历史数组排序。后续控制台可为该接口提供选择入口。

开放日期不绕过主线门槛：普通活动要求完成 1 章 1 话，委托要求完成第 3 章，凶化厄灾要求完成第 6 章。关卡自身前置和试玩条件继续生效。

不同活动 ID 的进度、次数、奖池和战绩分开保存。同一 ID 重新开放不会清空已领奖记录。`epoch` 用于识别实例；本批不自动重置同一活动实例，也不提供控制台重置操作。已合法进入的战斗可在到期后结算，但仍检查活动归属、实例及重置版本；新的参加、开战、恢复和扫荡继续检查档期。

## 奖励、任务与兑换

236 条活动任务按真正的 `m_mission_terms.category_group` 归属处理，其中 208 条限时任务、28 条限时日任务。任务编号前缀不作为活动归属依据。剧情任务使用原生战斗定义 ID，不能把剧情节点 ID 当作同一 ID。

回想和活动剧情共用首奖领取记录；已阅读不直接等于活动战斗前置完成。首通奖励、通关次数、普通重复奖励分别维护。扫荡累计通关次数，不伪造最快时间、最高 FC 或限制队伍战绩。重复读取旧任务请求会刷新当前数值和领取状态。

活动货币是 `content_type=54`，首领券是 `56`，全局时限资源是 `120`；抽卡代币 `170` 与活动币分开。活动币进入既有背包和兑换事务，箱池、棋盘与兑换使用同一余额。

普通体力关、主线周回和常驻外传能产出已参加活动的体力币，并触发匹配奖励关。基础币按原生公式 `ceil(体力 × boost_rate / 1000 / stamina_base)` 计算，没有匹配倍率则为零。当前 600002 活动的倍率为 750，40 体力得到 30 枚基础币。结算与扫荡返回实际活动掉落。

角色掉落加成按出发／上次通关阵容冻结，并按奖励类型和 ID 匹配。狩猎首领关的升级效果由原生 `StageEffectModel` 能力链应用；服务端写入等级和开关，不重复把同一效果叠入角色数值。

## 明确的本地规则

无法从客户端恢复的服务器规则保留为本地实现：

- 采矿单场矿战默认 60 秒，`event_miner_battle_seconds` 可调整；补给默认 3 次。两种次数购买默认每日 3 次、每次 50 钻石，对应 `event_miner_recovery_*`、`event_mutant_recovery_*`。
- 凶化厄灾榜单仅显示当前真实本地玩家。`event_mutant_ranking_reward_on_query=1` 时，有有效挑战成绩后首次查询按个人榜名次发一次邮件；设为 `0` 关闭这项本地发奖策略。这不是官方多人榜或截止结算算法。
- 棋盘按模板洗牌，箱池按剩余数量抽取。奖励关使用主表基础概率、失败递增和成功重置；角色加成只叠在本次阈值上，不污染基础概率。`event_bonus_character_rate_scale=1000` 表示完整应用主表角色加成，`0` 表示关闭。
- 遭遇活动的额外每日容量、首次加入补足及当前活动选择属于本地规则。当前 18 期混入普通地图的概率字段均为零；未来非零值需要单独适配。当前奖励关编队限制组全为零，非零新规则也需重新核对。

旧凶化厄灾 1050001 缺少原始首领显示元数据。衍生视图补入保留 ID `99001050001`，名称取实际敌人，显示属性为原生允许的 `None=0`；真实敌人、阶段和战斗属性不变。该显示记录不会加入普通厄灾的出现列表。

## 资源与验证边界

资源审计覆盖 30 个活动、333 个活动战斗定义、60 个脚本和 6,193 处动态引用。1,068 个检查键中 1,057 个可验证；1,097 个依赖包中 1,087 个通过本地大小和 SHA-256 检查。缺少的 10 包均为活动背景，已解析的战斗场景、敌人模型及矿车资源没有发现缺包。

背景缺项为 `abg11101a`、`abg20200b`、`abg14200a`、`abg20400a`、`abg20300a`、`abg11500a`、`Functionbg012`、`abg11200a`、`abg10100a`、`abg14900a` 对应的 Event BG 预制体。原目录、StreamingAssets 和游戏缓存未找到这些包；匿名官方地址下载未成功，返回 403 或 SSL 连接中断。未用剧情 PNG 冒充预制体，也未修改真实资源清单。

详细接口、原生证据、隔离测试及资源结果见 `artifacts/pc-research/events/`。原生操作、页面布局、剧情音效容错、真实战斗表现、档期切换与客户端重启仍需用户要求实机检查后验证。

初次联合回归曾因整份主表被重复保留而耗尽内存，该次结果未采用。当前视图共享未修改的原始数据，仅复制改动行，并在应用关闭时释放缓存；最后验证使用独立进程分批运行选定模块，不运行全项目测试套件。

最终选定 239 项检查，238 项在分批运行中直接通过；一项旧回想测试缺少“教程已完成”前置，补齐测试准备后单项通过。没有未解决的测试失败，详见 `targeted-batches.json`、`recollection-prerequisite-regression.xml` 和最终 `implementation-audit.json`。真实存档尚未写入本批活动数据；后续实际使用后如需回退源码，应同时恢复匹配的存档备份。
