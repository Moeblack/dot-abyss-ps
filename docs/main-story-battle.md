# 主线战斗与教程

本批实现主线章节、主线重复刷关和扫荡，以及新档序章教程。当前是源码和离线接口验证阶段；没有部署、重启服务、修改真实存档或运行原生客户端验收。

## 支持流程

- 主线剧情的验收口径是完整流程：章节进入、战前剧情正常播放或跳过、战斗、战后与纯剧情、整关通关、下一章开放；还包括中途退出后的续接、已读状态和已解锁剧情回看。对白、配音、背景、角色演出及脚本选项由原生剧情系统执行，不能用服务器序列推进代替播放验收。
- 主线：剧情序列、开战、地下城与防卫战场、胜利结算、首通奖励、末尾剧情、整关奖励、下一关开放。
- 会话：开战重试复用同一场，重启服务后读取同一战场；失败、放弃和取消会话不推进章节。
- 重复关：通关区域后开放，重复开战和结算不重复发章节及首通奖励；扫荡每次 1–100 场，按主表体力乘次数扣除。
- 教程：新 PC 存档从状态 0 开始，按原生 0→…→13→99 推进；两个教程战使用固定队伍与 `party_no=0`，教学抽卡确认后继续。教程战不扣体力。
- 正常解锁：整关完成、指定剧情序列完成、满足好感等级的员工数量。新档隔离旧的快捷全开配置，旧档保留已有进度和开关。
- 任务联动：整关完成、体力消耗、击杀总数和指定敌人种类会更新相应统计；重复结算不重复计数。

主线开战返回的 `quest_id` 是战斗主表 ID；重复关同样使用战斗 ID。教程返回教程关卡 ID。`stage_detail`、`party_detail` 保持原生要求的 JSON 字符串，`session_detail` 使用已采样的空值。

战斗运行、动作与伤害计算由原生客户端执行。后端校验本局实体、击杀条件和掉落来源，不完整复演伤害过程。会话恢复保留最初战场与抽选结果，不恢复未上传的逐帧战斗现场。

## 数据与防重复

会话、首通回执和整关奖励保存在既有 `gameplay_progress.features` 中，与玩家记录共用 SQLite 事务。失败会回滚体力、奖励和进度。会话实体 ID 按持久序号生成，重开后旧战报不能结算新场。

旧档第一次加载时按已有章节序列建立历史领奖基线，不补发已经越过的战斗和章节奖励。新档教程标记只在真正创建存档时写入，不能根据状态值误判旧档。

旧版本不认识新增的进度分区；加载新版并保存后若要回滚，应同时恢复对应的存档检查点。

接口重试回包只刷新原回包涉及的记录，使用各记录自己的主键；已删除记录发送删除通知。重试既不重新发奖，也不把客户端章节、教程或余额显示回退到旧值。

主线失败和放弃保留已经消耗的体力，这是当前本地规则。扫荡复用真实战场和结算函数；整批成本、全部奖励和次数在同一事务中提交。

目标为 0 的“任意主线”任务存在旧周回文案和当前主线文案，采用“已完成的主线任务数＋成功重复战斗次数”的本地兼容计数。指定敌人种类按敌人主表的 `m_job_id` 统计。深渊等其他模式的任务计数不由主线代填。

## 可配置本地规则

当前资源没有完整官方掉落组、部分敌群生成参数和防卫波次表。以下规则不声称复现官方隐藏算法，可在数据目录 `gameplay-rules.json` 调整，后续操作读取新配置；已经开始的战场与掉落保持原抽选结果。

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| `battle_drop_probability_per_mille` | 300 | 每个敌人或资源来源生成一项公开掉落的概率，0 关闭 |
| `battle_rare_drop_probability_per_mille` | 50 | 普通和稀有池同时存在时，选择稀有池的概率 |
| `battle_player_exp_per_stamina` | 1 | 胜利时每点本场体力对应的玩家经验 |
| `battle_first_reward_group_mode` | 2 | 0 关闭首通奖励；1 使用区域奖励组基数；2 加上任务顺序偏移 |
| `battle_dungeon_lottery_weighted` | 1 | 1 按已保存敌群权重抽选，0 均匀抽选 |
| `battle_defence_enemy_copies` | 1 | 防卫关公开敌人条目对应的普通敌人数 |
| `battle_defence_enemy_energy` | 300 | 本地构建的普通防卫敌人能量掉落 |

首通奖励组模式在首战样本中匹配，其他关卡仍属于明确的本地兼容策略。关闭首通奖励也记录该节点已处理，之后切换配置不会回补同一场奖励。

额外掉落使用主表的 `addition_extra_drop_probability`，叠加已生效的研究、VIP 和订阅加成，封顶千分之一千。当前本地策略是在基础掉落生成后再抽选一份额外奖励，绑定独立的本局 ID，结算标记为额外掉落；不会在结算重试时重新抽取。

原始缺失字段采用保守名称并校验完整表指纹；主数据变更时会要求重新确认绑定，不会静默把新版本字段套进旧算法。

## 验证边界

本轮合并定向测试 113 项通过，无失败或跳过；报告为 `artifacts/pc-research/battle/combined-targeted.xml`。没有运行全项目测试。

定向检查包括：真实主表全部 179 个战斗定义和 3 个教程战场、单一隔离存档连续推进 207 个任务与 178 个实际主线战斗节点、教程完整 HTTP 流程、重复请求、非法战报、事务回滚、历史存档和记录主键兼容。

主线关联的 118 个剧情节点均能找到定义、剧本文本和配音入口；已核对其声明依赖的 270 个资源包 SHA256。该检查不等于逐条脚本动态资源或原生播放验收，详情见 `artifacts/pc-research/battle/main-story-narrative-assets.json`。主线回看权限另通过一项定向验证。

原生战斗画面、敌人分支行进、角色技能与研究效果、胜败动画、实际难度及重复关扫荡画面仍需实机验收。构建成功或提交测试胜利结果不代表这些画面已验收。

`m_evaluate_*` 和 `require_drop_cost` 保留在原始主表中，但当前数据没有对应评定表，现役主线回包也没有旧 `ChapterQuestClearQuest` 的星级奖励字段。这些字段的当前用途仍待确认，没有另造星级奖励。

其他独立战斗模式、活动与复刻、控制台不在本批范围。第三个教程配置存在且可构建，但尚未确认其当前实际入口，不会把主线首战的功能引导错误绑定到它。

证据和定向测试记录位于 `artifacts/pc-research/battle/`。
