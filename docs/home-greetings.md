# 主页角色礼物

普通礼物按本地规则每天北京时间 04:00（日本时间 05:00）刷新。到点后的首次主页请求生成新批次；关游戏、重新登录、领取礼物和好感变化都不重抽当前批次。

## 抽选与领取

- 每批默认 3 位，受 `home_greeting_limit` 控制；从已拥有且满足好感条件的角色中抽选，每位角色只占一个位置。
- 尚未完成的好感剧情优先，同一角色依好感门槛顺序出现；其余位置随机抽选普通礼物。
- 普通礼物位置随机选择；剧情配置了固定位置时优先保留，位置冲突时改用空闲位置。
- 名单、位置、截止时间和领取凭证一起保存。领取后不补位，重登仍返回 `is_received=1`，由原生客户端隐藏礼物。
- 好感剧情按 `t_novel_homes` 中的剧情 ID 只领取一次。新解锁剧情进入下一批候选，不覆盖当前已领普通礼物。
- 同一次请求重试沿用原回包；使用新请求重复领取返回空奖励，不再增加道具。发奖和凭证由同一个存档事务提交。

`home_greeting_reset_hour` 使用日本时间，取值 0–23，默认 5。控制台可以修改；当前批次不会因此提前刷新。把刷新时间调晚时会延长当前批次，避免同一天多发一批。访客的日期和收据也使用同一生效周期；访客开关仍默认关闭。

当前主表有 11 组完全重复的普通问候条目，抽选时按角色合并，避免这些角色获得双倍抽中概率。旧记录引用重复条目时保留原 ID。

## 旧存档

首次访问主页时自动建立批次，兼容旧日本自然日和新日界之间的领取凭证。已经领取的礼物保留已领标记，原有未领剧情尽量保持原入口。旧凭证和剧情完成记录保留，不追扣历史多领的奖励。

迁移不改变存档外层格式，只在 `features.home.data` 增加 `greeting_cycle`。不支持此字段的旧服务端不能读取迁移后的主页状态；回退代码时应恢复修改前的存档备份。

## 证据与验证

原生代码和官服采样确认了同批名单稳定、领取标记以及独立的剧情完成记录。刷新时刻、随机分配和剧情一次性奖励是本地规则；刷新时刻由用户指定，未声称复刻未知的官服算法。

定向检查覆盖领取后重启、并发领取、午夜与刷新边界、随机名单与坐标持久化、剧情顺序、旧凭证迁移和规则热更新。记录位于 `artifacts/home-greetings/`；原生与采样证据位于 `artifacts/pc-research/home-greeting-native-evidence.md`。本轮未运行全项目测试。
