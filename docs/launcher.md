# 启动器与存档管理

本次补齐中文目录、列表滚动、游戏启动、创建存档和中文存档名称。入口保持 start-console.cmd / start-console.ps1。

## 首次配置源码仓库

仓库不含游戏安装目录、资源、主数据原包或插件依赖。现有运行环境默认使用相邻的 `dotabyss_pc/local-client` 和 `dotabyss_pc/toolchain/runtime`，本地数据位于 `data-pc-1.15.0`。

将 `pc/releases/pc-1.15.0.example.json` 复制为同目录的 `pc-1.15.0.json`，把资源种子路径中的 `YourName` 改为实际路径。现有本机配置文件无需覆盖。通过 `pc/prepare-client.ps1` 准备客户端副本，安装匹配的加载器和编译后的本地插件；主数据与资源导入流程见 [主数据](masterdata.md) 和 [资源](assets.md)。

这些路径下的本地文件均不加入 Git。环境配置完成后再从启动器启动服务和游戏。

## 窗口行为

启动器展示当前编辑档与运行游戏档。初次打开时优先当前运行档或唯一在线档，再恢复浏览器记住的选择，最后使用已配置或已初始化档。用户手动切换后不会被后台心跳自动改回。

运行中的游戏若属于另一档，启动按钮禁用并提示先退出游戏。可以选择查看游戏使用的档，也可以继续查看其他档的数据。在线状态对应当前所选档，另一档在线不再只显示含糊的“客户端离线”。

目录和字段有中文标签，技术键名作为辅助信息保留。中文译名位于独立 display 元数据中，原始值继续用于编辑、存档和接口请求。用户自己填写的昵称和队名不会被翻译替换。

表格优先展示编号、名称等字段，最多展示七列，其他字段可点行查看。列宽超出面板时使用独立横向滚动区，名称可换行；选择器占满所在面板，并支持中文和原始键搜索。

## 存档数据

新增 profile_labels、profile_create_receipts 表，旧 profiles.name 保持为内部 ASCII 登录标识。可见存档名称支持 Unicode，最多64个可见字符，重复名称按规范化和大小写折叠检查。

新建档案的内部键自动生成，使用现有初始数据和 guided 教程策略。游戏昵称遵守当前规则长度；留空时优先用存档名称，超过昵称长度上限时使用“司令官”。新建档案、原生记录、玩法进度、显示名称与幂等回执在同一 SQLite 事务中保存。

重命名需要匹配原显示名称，避免覆盖其他窗口的改名。重命名不改变原登录标识、游戏昵称、角色或进度。

## 启动与安全边界

游戏启动 API 只接受 profile_id，不接受任意命令或可执行路径。启动器核对固定客户端清单、数据版本、资源和插件配置，备份 pc-local.json，再写入所选内部标识与当前本机服务地址。进程启动失败时恢复配置；运行中的游戏不会被自动终止。

操作系统文件锁防止同时启动。运行档案通过进程编号、创建时间以及该进程启动后的有效心跳识别，不能只凭当前配置文件推断。无法确认同名进程归属时阻止再次启动。

启动器通过独立本机端口提供页面。顶部“启动服务”使用当前项目固定的 Python、数据目录和模块，后台启动后等待健康检查与管理接口就绪。停止、重启通过仅属于该子进程的标准输入管道发出正常停机信号，等待请求结束；超时保留停止中状态。外部启动的服务只连接，迁移到启动器管理时需要先从原窗口停止一次。

关闭浏览器窗口不关闭后台启动器或游戏服务；再次打开会复用同一配置的启动器。停止游戏服务后外壳页面仍保留，服务重启后自动申请新票据并重新显示工作台。顶部刷新按钮可手动重新连接工作台；自动轮询不会反复重载表单。

控制器只开放本机访问，校验 Host、Origin、窗口会话和固定动作，不接收任意程序路径或命令。后台进程与服务日志保存在 `artifacts/launcher/`，日志在界面中按大小截断并遮蔽管理凭据。原有管理 API 与存档格式不变。
